# Decisions

Design and scope decisions made by the lead developer, newest last. The owner's own decisions on the SRS's open questions are in `docs/LEAD_DEVELOPER_BRIEF.md` section 4 and are not repeated here. Each entry says what was decided, why, and how to reverse it.

| # | Date | Decision | Why | To reverse |
|---|---|---|---|---|
| D-001 | 2026-11-11 | CI runs on `ubuntu-latest` again, with Playwright kept current by Dependabot. | The `ubuntu-24.04` pin was a stopgap for Playwright 1.58. A pinned image fails outright the day GitHub retires it; a floating image with a current Playwright fails only if Playwright falls behind. | Set `runs-on` back to a fixed image in `.github/workflows/ci.yml`. |
| D-002 | 2026-11-11 | The backend installs from hashed lockfiles (`requirements.txt`, `requirements-dev.txt`) compiled from `requirements.in` files. `pip-audit` runs in CI from its own pinned install and is not in the lockfile. | MNT-7. Hashes make every build install byte-identical packages. `pip-audit` pulls in forty-odd packages that the app never imports. | Delete the `.in` files and maintain `requirements.txt` by hand. |
| D-003 | 2026-11-11 | Dependency audits gate every pull request: any `pip-audit` finding, and any `npm audit` finding rated high or critical in a production dependency. An accepted exception is added to the CI command with `--ignore-vuln` and recorded here. | SEC-4. A gate that only warns is not read. | Remove the `dependency-audit` job. |
| D-004 | 2026-11-11 | Backups are a Compose service built from `postgres:16`, not a host cron job, and the old Python backup scripts are removed. Daily dumps keep 14 copies; a separate pre-deploy dump is taken before every deploy and keeps 5. | The droplet can only be changed through the deploy workflow. `pg_dump` in the API image would not match the server version for long. Pre-deploy dumps are kept apart so that a day of many deploys does not push out the daily copies. | Remove the `backup` service; nothing else depends on it. |
| D-005 | 2026-11-11 | A restore test runs on every deploy and in CI, into a scratch database. | REL-3 asks for a test every three months. Run on every deploy it costs seconds and cannot be forgotten. | Delete the workflow step. |
| D-006 | 2026-11-11 | The API and frontend ports are bound to `127.0.0.1` now, ahead of the proxy in WP-2. | Nothing could reach them through the firewall anyway, and the firewall should not be the only protection. The deploy smoke tests use the loopback address. | Change the `ports` entries in `docker-compose.yml`. |
| D-007 | 2026-11-11 | The `zones` table is dropped (migration 023). | The roadmap asked for a decision. Its seed rows (a mixing area, an incubation tent, fruiting tents) do not describe the farm's sites, and nothing has referred to it since March. Bag location (BAG-10) needs site and room, and will get a table designed for that. | Recreate the table in a new migration. No data is lost: it held three seed rows. |
| D-008 | 2026-11-11 | A time sent to the API without a UTC offset is refused (422). Every time in a response is UTC with its offset. | SRS 5.2. A time with no offset would be stored as if it were UTC, four or five hours off for an Eastern farm, and the mistake would be invisible. The screens already send an offset. | Change `InputDatetime` in `backend/app/schemas.py` to accept naive values and decide which zone they mean. |
| D-009 | 2026-11-11 | A run's planned bag count is limited to 999. | RUN-3 needs an upper bound to keep bag numbers within the label format (BAG-5). The farm starts fewer than 100 substrate bags a week. | Raise `le=999` in the run schemas; bag codes for such a run would exceed 18 characters. |
| D-010 | 2026-11-11 | Status `CREATED` is no longer produced. A bag with no stage recorded reads `STERILIZED` or `PASTEURIZED`. | MNT-3. The two old code paths differed exactly here. SRS 3.2 says a bag record is created from a run that has already been heat-treated, and no screen or filter knew `CREATED`. | Restore the branch in `_derive_bag_status`. |
